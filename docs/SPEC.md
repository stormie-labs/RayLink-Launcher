## 0. Цель, границы, термины

**Сценарий владельца:** «играю с другом, поймали баг, написал тебе, ты сделал, мы быстро обновили и дальше играем».
Тестер нажимает одну кнопку: его стенд обновляется до последней сборки, и можно играть.

**Лаунчер делает:**
- один раз собирает **стенд** из установок тестера: Anomaly и, если есть, профиль MO2 GAMMA;
- узнаёт о новых сборках на GitHub, качает только **наш слой** (~10 МБ), проверяет хэши, ставит транзакцией;
- откатывает на прошлую сборку;
- пересобирает **слой GAMMA**, только когда изменилась GAMMA тестера;
- запускает «Создать игру» и «Подключиться», при желании — второе окно на этом ПК;
- до запуска спрашивает хоста: «у тебя та же сборка и тот же набор модов?»;
- собирает логи в архив.

**Лаунчер не делает (v1):**
- не пишет в папки Anomaly, MO2 и модов тестера. Даже exe в `<Anomaly>\bin` не кладёт, в отличие от `deploy.ps1` S0;
- не правит `modlist.txt` и настройки MO2;
- не ставит GAMMA и Anomaly;
- не ищет серверы, не пробивает NAT, не загружает логи на сервер;
- работает только на Windows 10/11 x64.

**Термины.**

| Термин | Значение |
|---|---|
| Стенд | Отдельная папка тестера, например `E:\QuarkNET`. В ней корень игры `game\` и служебная `.quarknet\` |
| Наш слой | Слои Engine (exe + `engine\gamedata`), Core (`gamedata`) и GAMMA-патчи (`gamedata_gamma`) — то, что выпускаем мы |
| Слой GAMMA | Включённые моды профиля MO2 и `overwrite` в порядке приоритета MO2. Жёсткие ссылки на файлы тестера |
| Сборка N | Целый номер, растёт: «Сборка 10». Один номер = один набор файлов нашего слоя |
| Канал | Репозиторий GitHub с релизами сборок и вид: «стабильные» или «свежие» (prerelease) |
| Хост / напарник | Тот, кто создал игру / тот, кто подключается |
| Протокол | `kProtocolVersion` движка. Разный протокол — играть вместе нельзя |

**Критерии готовности v1** (проверяются в PLAN T12):
1. Новый тестер с Anomaly 1.5.3 и GAMMA на одном томе проходит мастер и видит «ИГРАТЬ». Стенд на 62 тыс. файлов
   собирается не дольше 60 с на SSD; `mo2_stand.py` делал это за 31,5 с.
2. Новая сборка ставится одной кнопкой. Обновление нашего слоя: скачивание ~10 МБ, установка не дольше 5 с.
3. Прерванная установка — убитый процесс, выключенный свет — при следующем запуске доводится или откатывается сама.
   Стенд всегда ровно на одной сборке.
4. За всю работу лаунчер не меняет ни одного байта и атрибута вне стенда и своих папок `%APPDATA%`/`%LOCALAPPDATA%`.
   Проверка — тест на фейковой ФС и Process Monitor на живой машине.
5. «Проверить» за ≤ 3 с говорит одно из трёх: «та же сборка и моды», конкретное отличие или «хост не отвечает».
6. Токен не встречается ни в одном файле, логе и архиве логов.

## 1. Технологии

### 1.1 Оболочка: Tauri v2
- **Tauri v2** — Rust-ядро и системный WebView2. Exe ~10 МБ, установщик ~8–12 МБ с кадрами и шрифтами.
  У Electron 100+ МБ и свой Chromium.
- **Rust** даёт файловую систему, сеть, процессы и Win32 без посредников. Это жёсткие ссылки, удаление ссылок на
  read-only файлы, junction, сокеты и Credential Manager.
- **WebView2** на машине владельца — 155.0.4283.62 (проверено 2026-10-23 23:24). В Windows 11 он есть всегда.
  Для Windows 10 установщик несёт `embedBootstrapper`.
- **Rust установлен** 2026-10-23 23:22: rustc/cargo 1.99.1, `x86_64-pc-windows-msvc`, clippy, rustfmt.
  Windows SDK 10.0.26100 есть (VS 2022 BuildTools собирает движок).

### 1.2 Фронтенд: Vite + TypeScript (strict) + Svelte 5

| Критерий | Чистый TS | **Svelte 5** | Solid |
|---|---|---|---|
| Анимации из DESIGN §8: поворот компаса, сегменты, галочки по одной, появление сборки | Руками: классы, `animationend`, порядок выхода | Встроенные `transition:`/`in:`/`out:`/`animate:flip`; длительности из токенов; выход элементов из коробки | Нужен `solid-transition-group`, выход — отдельная обвязка |
| Бандл (рантайм) | 0 | ~10–15 КБ gz; компилятор выкидывает лишнее | ~7 КБ gz |
| ~25 состояний дока, мастер, задачи с прогрессом | Ручная синхронизация DOM — главный источник багов | Руны `$state`/`$derived`; логика выносится в чистые TS-модули | Тонкая реактивность, но JSX |
| Перенос HTML-прототипов дизайнера | Прямой | Почти прямой: разметка HTML и scoped CSS в компоненте | Переписать в JSX |
| Тесты | Vitest + DOM | Vitest + `@testing-library/svelte`, Playwright | Vitest + `@solidjs/testing-library` |

**Решение — Svelte 5 без SvelteKit**, обычный SPA на `@sveltejs/vite-plugin-svelte`.
- Причины: анимации и выход элементов встроены, бандл маленький, прототипы `design/*.html` переносятся почти
  копированием разметки и CSS.
- Правило: вся логика состояний — в чистых TS-модулях (`src/lib/state/*.ts`) с табличными тестами Vitest.
  Компоненты только рисуют.
- Строгость: `strict`, `noUncheckedIndexedAccess`, ESLint `no-explicit-any: error`, `ban-ts-comment: error`.
  Данные от бэкенда валидируются схемами `valibot` (~1–2 КБ).
- Движение: CSS и transitions Svelte на токенах `--dur-*`, `--ease-*` из DESIGN §8. Анимируются только
  `transform`/`opacity`, прогресс — `scaleX`.

### 1.3 Окно
- 1280×760, `decorations: false`, `resizable: false`, `maximizable: false`, `center: true`, `shadow: true`.
- Своя полоса заголовка 36 px с `data-tauri-drag-region`, кнопки «свернуть» и «закрыть» 46×36. Двойной клик не
  разворачивает окно: оно фиксированное.
- Один экземпляр: `tauri-plugin-single-instance`. Второй запуск поднимает первое окно.
- **Reduced motion.** По runbook vault WebView2 отдаёт `prefers-reduced-motion: reduce`, когда в Windows выключены
  «Эффекты анимации». У владельца они выключены.
  - Окно создаётся в Rust с `additional_browser_args("--force-prefers-no-reduced-motion
    --disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection")`. Дефолтные флаги wry повторяются: свой аргумент
    их заменяет.
  - Решение о движении принимает приложение. Настройка «Анимация»: полная (по умолчанию) / спокойная / выключена /
    как в Windows.
  - «Как в Windows» — команда `motion_system_reduced` (`SPI_GETCLIENTAREAANIMATION`). При фокусе окна значение
    перечитывается.
  - Экран обязан хорошо выглядеть и без движения.

### 1.6 Граница ядра и WebView
- Файлы, сеть, процессы и секреты — **только в Rust**. У WebView нет прав `fs`, `shell`, `http`.
  - Разрешено (capabilities): окно (свернуть, закрыть, перетаскивание), `dialog:open` для выбора папки, наши
    команды — явным списком из PLAN §2.1 (`tauri_build::AppManifest::commands`).
- Команды принимают не произвольные пути на запись, а «намерения»: «собери стенд в X». Rust сам проверяет X
  (§4.3, §8.5).
- CSP: `default-src 'self'; img-src 'self' data:; style-src 'self'; connect-src ipc: http://ipc.localhost`.
  Внешних запросов из WebView нет. Динамические стили — через `style:` Svelte (CSSOM), а не атрибут `style=""`.

Правила:
- **Одна кнопка.** «ИГРАТЬ» при скачанном обновлении сначала ставит его (секунды), потом запускает игру.
  - Если обновление ещё не скачано — качает, проверяет, ставит, запускает.
  - Исключения:
    - сборка закреплена (§3.8);
    - режим «Подключиться», и последняя проверка этого адреса (≤ 60 с) показала, что хост на нашей текущей
      сборке. Тогда играем на текущей, подпись «играю на 10, как у хоста; 11 поставлю потом».
- В режиме «Подключиться» нажатие «ИГРАТЬ» без свежей проверки (> 60 с) сначала проверяет хоста (≤ 2,5 с).
  - Строки 9–12 блокируют запуск.
  - «Хост не ответил» запуск не блокирует: хост может ещё грузить мир.
- Если у хоста `stand = null` (хост без лаунчера, §5.6), сборка и моды неизвестны. Подпись «у хоста стенд без
  лаунчера: протокол 10 совпадает; остальное сверит игра», запуск разрешён.
- Галочки проверки появляются по одной с шагом 80 мс (DESIGN §8).

### 2.3 Обновление: прогресс и шаги
- Сегменты «**качаю · проверяю · ставлю**» шириной 1,3 : 1 : 1, как полоса здоровья HUD.
  - Активный сегмент заполняется `scaleX` и бежит штриховкой; при reduced motion штриховка стоит.
  - Текст: «качаю 6,2 из 9,4 МБ · 3,1 МБ/с», «проверяю 212 из 340 файлов», «ставлю 34 из 340».
- Для первой сборки и пересборки GAMMA шаги свои: «**сканирую · связываю · ставлю**», текст «связываю
  41 200 из 62 030 файлов».
- **Ошибка шага:** сегмент красный, текст ошибки по коду (§2.8), «Повторить».
  - Ошибка до шага «ставлю» стенд не трогает.
  - Ошибка во время «ставлю» — автоматический откат на прежнюю сборку и текст «вернула 10: <причина>».
- **Отмена** — только на шаге «качаю». Частичная загрузка остаётся (`.part`) и докачивается в следующий раз.
- Игра запущена: «качаю» и «проверяю» идут, «ставлю» ждёт закрытия игры (строка 3).

### 2.4 «Обновления»
- **Сверху — строка канала:** «Канал `owner/quarknet-builds` · свежие · проверено 21:44 · Проверить». Состояния:

- **Слева — список сборок.** Номер 36 px, дата, значок «протокол 10», метки «у тебя», «в кэше», «на GitHub»,
  «ставится», «закреплена».
  - Сборка с другим протоколом помечена: «несовместима с 10: играть вместе можно, только когда обновятся все».

- **Действия:** «Обновить до 11» (песочная — главное действие экрана), «Откатить на 9», «Закрепить на этой сборке» /
  «Снять закрепление».
- **Пусто:** «Канал пуст — сборок ещё нет» или «Нет связи — показываю сборки из кэша».

### 2.5 Мастер первого запуска
Тот же язык B. Сверху сегменты шагов, «Назад/Далее», шаг виден целиком без прокрутки.
1. **Где игра.**
   - Автопоиск при входе, бюджет 3 с, отменяемый: «ищу на C:, D:, E:…».
   - Найденное — списки с радиокнопками: Anomaly (путь, версия, диск) и MO2 (путь, «GAMMA», профили).
   - Профиль — выпадающий список, по умолчанию `selected_profile` из `ModOrganizer.ini`.
   - Ещё есть пункт «Без GAMMA — чистая Anomaly» и «Указать вручную» (диалог папки).
   - Проверки: у Anomaly есть `db\`, `gamedata\`, `bin\`, `fsgame.ltx`; у MO2 есть `ModOrganizer.ini`,
     `profiles\<p>\modlist.txt` и папка модов; `gamePath` MO2 совпадает с выбранной Anomaly (иначе предупреждение).
   - **Процессор без AVX** — блок: «Сборка QuarkNET требует AVX — на этом процессоре не запустится».
2. **Куда ставить стенд.**
   - Предлагается `<том модов>:\QuarkNET`.
   - Галочки: «NTFS», «тот же диск, что Anomaly», «тот же диск, что GAMMA», «папка пустая или это наш стенд»,
     «пробная ссылка создана».
   - «Свободно 412 ГБ · нужно ~3 ГБ» и «Твои Anomaly и GAMMA не меняются».
   - Флажок «Второе окно на этом ПК (для проверки в одиночку) — нужно ≥ 32 ГБ ОЗУ с GAMMA».
3. **Ник** — «как тебя увидят напарники». 2–24 символа `[A-Za-z0-9_.-]`, по умолчанию — имя пользователя Windows,
   очищенное. Кириллицы нет: движок берёт ANSI-командную строку и `string64` (§5.4).
4. **Канал обновлений.**
   - Репозиторий подставлен при сборке лаунчера (`channel.default.json`).
   - Поле ключа — пароль. Видно, только если канал закрытый или проверка ответила «нужен ключ».
   - «Проверить канал» → «Найдена сборка 11 от 23.10 22:10» или ошибка.
5. **Сборка стенда.** Кнопка «Собрать стенд». Шаги «качаю · связываю · ставлю», затем «Готово» и переход на главный
   с «ИГРАТЬ».
   - Если MO2 открыт — предупреждение: «MO2 открыт: если он обновляет моды, стенд соберётся из половины. Закрой
     MO2 или продолжи».

### 2.6 «Настройки»
- **Игра:** пути Anomaly, MO2, профиль.
  - Папка стенда: «Перенести» = собрать новый стенд в другом месте; старый остаётся, его можно удалить безопасным
    удалением, §4.2.
  - Второе окно (вкл/выкл — достраивает или убирает `bin_b`, `appdata_b`, `fsgame_b.ltx`).
  - Размер теней `-smap` (по умолчанию 2048, как `launch.ps1`), статус коопа в лог каждые N с (`-coop_autostatus`,
    по умолчанию 60).
- **Профиль:** ник.
- **Канал:** репозиторий, вид «стабильные / свежие», ключ: «Задать», «Удалить», показывается только «ключ
  сохранён». «Проверить канал».
- **Обновления:** «Качать сразу» (вкл), «Ставить перед игрой: всегда / спрашивать», «Хранить сборок: 3» (2–10),
  закрепление.
- **Внешний вид:** «Анимация: полная / спокойная / выключена / как в Windows».
- **Лаунчер:** версия, «Проверить обновление лаунчера».

### 2.7 «Помощь»
- **Отправить логи** (§6.1): список файлов с размером, «Сохранить в папку», «Скопировать файл в буфер». Результат —
  «Архив `QN-7F3A` сохранён — пришли его в чат».

- **Откатить** (§3.8): цель, подтверждение.

- **Если не подключается** — чек-лист:

- **О лаунчере:** версия, лицензии шрифтов (OFL).

## 3. Канал обновлений

### 3.1 Репозитории
- **Сборки:** отдельный репозиторий только для релизов, например `<owner>/quarknet-builds`. Кода в нём нет; коммит
  с README нужен, чтобы ставить теги.
  - У `anomaly-coop` нет remote (проверено 23:24), у `engine` remote — апстрим xray-monolith. Публиковать код не нужно.
  - Приватный или публичный — решает владелец (§11). Лаунчер поддерживает оба.
- **Лаунчер:** релизы лаунчера в публичном `<owner>/quarknet-launcher` — для updater, §9. Если отдельного репозитория
  не будет, — тег `launcher-vX.Y.Z` в том же репозитории с `--latest=false`, чтобы `/releases/latest` оставался за
  сборками.
- **Тег сборки** — `build-<N>`, имя релиза «Сборка N», тело — changelog для игрока (markdown).
  - «Свежие» = prerelease. `publish.ps1 -Promote N` снимает пометку и делает сборку latest.

### 3.2 Ассеты релиза
| Ассет | Содержимое |
|---|---|
| `manifest.json` | §3.3 |
| `manifest.json.sig` | Подпись minisign/ed25519 (P1 — после первых релизов, §8.3) |
| `engine-bin-<sha12>.zip` | `bin/AnomalyCoopDX11AVX.exe` |
| `engine-gamedata-<sha12>.zip` | `gamedata/**` движка (`git -C engine archive HEAD gamedata`) |
| `core-gamedata-<sha12>.zip` | `gamedata/**` проекта (`git archive HEAD gamedata`) |
| `gamma-gamedata-<sha12>.zip` | `gamedata/**` из `gamedata_gamma` (может быть пустым) |

- Пак назван по своему sha256 (`sha12` — первые 12 hex). Пак, не изменившийся с прошлой сборки, лаунчер берёт из
  кэша и не качает.
- Внутри zip — разделитель `/`, порядок записей отсортирован, время записей фиксировано (2000-01-01). Тот же вход
  даёт тот же sha.

### 3.3 `manifest.json`
UTF-8 без BOM, LF. Пример:

```json
{
  "schema": 1,
  "product": "quarknet",
  "build": 11,
  "publishedAt": "2026-10-23T22:10:00+03:00",
  "prerelease": true,
  "protocol": 10,
  "maxPlayers": 8,
  "minLauncher": "0.1.0",
  "engine": {
    "commit": "adcfcf3…40hex",
    "exe": "bin/AnomalyCoopDX11AVX.exe",
    "exeSha256": "…64hex",
    "builtAt": "2026-10-23T21:42:00+03:00"
  },
  "project": { "commit": "d03f1aa…40hex" },
  "changelog": [
    { "kind": "new", "text": "Группа ждёт всех у перехода на другую карту", "hint": "Хост может уйти сразу — держи F" },
    { "kind": "fix", "text": "Хост не вылетает, пока клиент грузит карту" }
  ],
  "commits": {
    "engine": ["adcfcf3 World gate, second line: host_can_start, …"],
    "project": ["d03f1aa tests: world gate (20)"]
  },
  "packs": [
    { "id": "engine-bin", "layer": "engine", "asset": "engine-bin-3f9a1c2d4e5f.zip", "sha256": "…", "bytes": 4123456 },
    { "id": "engine-gamedata", "layer": "engine", "asset": "engine-gamedata-0a1b2c3d4e5f.zip", "sha256": "…", "bytes": 812345 },
    { "id": "core-gamedata", "layer": "core", "asset": "core-gamedata-9f8e7d6c5b4a.zip", "sha256": "…", "bytes": 1534567 },
    { "id": "gamma-gamedata", "layer": "gamma", "asset": "gamma-gamedata-112233445566.zip", "sha256": "…", "bytes": 1234 }
  ],
  "files": [
    { "path": "bin/AnomalyCoopDX11AVX.exe", "layer": "engine", "pack": "engine-bin", "sha256": "…", "bytes": 10485760 },
    { "path": "gamedata/scripts/coop_main.script", "layer": "core", "pack": "core-gamedata", "sha256": "…", "bytes": 12345 }
  ]
}
```

Правила (валидатор `qn-core::manifest`, он же `qn-tool manifest check` для `publish.ps1`):
- `schema = 1`, `product = "quarknet"`. Неизвестная `schema` — ошибка. Неизвестные поля игнорируются: так
  новые поля не ломают старый лаунчер.
- `build` ≥ 1. `protocol` и `maxPlayers` > 0. `minLauncher` — semver.
- `changelog[].kind` ∈ `new | fix | change | known`; `text` ≤ 200 символов, `hint` ≤ 200.
- `files[].path` — путь относительно корня игры стенда, проверка §8.4.
  - Разрешённые места по слою: engine — ровно `bin/AnomalyCoopDX11AVX.exe` и `gamedata/**`; core — `gamedata/**`;
    gamma — `gamedata/**`. Новые места — только со сменой `schema`.
  - Пути уникальны без учёта регистра в пределах слоя.
- Каждый файл ссылается на существующий пак того же слоя. В каждом паке ровно те файлы, что указаны
  (проверяется при распаковке).
- `engine.exeSha256` равен sha файла `engine.exe`.
- Общий размер распакованного ≤ 512 МБ, файл ≤ 128 МБ — защита от zip-бомбы.
- **Порядок слоёв в стенде:** игра → **engine** → моды профиля → `overwrite` → **core** → **gamma**. Это порядок
  `deploy.ps1 -Profile` и `MO2_GAMMA.md §3`.
  - Engine лежит **под** модами: 15 файлов движка перекрыты модами GAMMA.
  - Слой gamma ставится только в стенд GAMMA; в стенде чистой Anomaly его нет, как и в `package.ps1`.

### 3.4 Как лаунчер узнаёт о новой сборке
- Заголовки: `User-Agent: QuarkNET-Launcher/<ver>`, `Accept: application/vnd.github+json`,
  `X-GitHub-Api-Version: 2022-11-28`. С ключом добавляется `Authorization: Bearer <token>`.
- **Стабильные:** `GET https://api.github.com/repos/{o}/{r}/releases/latest`.
- **Свежие:** `GET /repos/{o}/{r}/releases?per_page=20`. Из ответа берутся релизы с тегом `build-<N>`, не draft;
  победитель — наибольший N.
- Потом скачивается ассет `manifest.json` выбранного релиза.
- **ETag:** запрос с `If-None-Match`. По документации GitHub ответ `304` не тратит лимит — проверить на живом
  канале (T12).
- **Когда:** при старте, раз в 10 мин, пока окно открыто, при фокусе окна (не чаще раза в минуту), по кнопке
  «Проверить» и сразу после проверки хоста, который оказался на более новой сборке.
- **Лимит:** без ключа 60 запросов/ч на IP, с ключом 5000. При `403/429` с `x-ratelimit-remaining: 0` ждём до
  `x-ratelimit-reset` и показываем время.
- `manifest.minLauncher` больше версии лаунчера → `UpdateInfo.state = launcherTooOld`.
- Сборка закреплена → лаунчер показывает, что вышла новая, но сам ничего не качает и не ставит.

### 3.5 Приватный репозиторий и ключ тестера
- Ключ — fine-grained PAT с правами только на чтение: Contents read, Metadata read, на один репозиторий сборок,
  срок ≤ 1 года.
  - Владелец делает один такой ключ и передаёт друзьям лично; или каждый тестер — коллаборатор со своим ключом.
- Хранится **только** в диспетчере учётных данных Windows: generic credential, цель
  `QuarkNET Launcher:github:<owner>/<repo>`, крейт `keyring` (windows-native).
  - Не хранится в `settings.json`, логах, архиве логов, URL, переменных окружения, состоянии фронтенда.
- **Ввод:** поле-пароль → команда `channel_set_token`.
  - Rust сразу проверяет ключ: `GET /repos/{o}/{r}` с ключом, нужен `200`. Только после этого сохраняет.
  - Фронтенд сразу очищает поле и в store ключ не кладёт. Обратно приходит только `hasToken: true`.
- В памяти ключ — `secrecy::SecretString`. Заголовок помечается `HeaderValue::set_sensitive(true)`.
  `Debug`/`Display` редактируются (§8.1).

### 3.6 Скачивание
- **Публичный канал:** ассет по `browser_download_url`.
- **Приватный канал:** `GET {asset.url}` с `Accept: application/octet-stream` и ключом. Ответ `302` на подписанный
  URL.
  - Редиректы **обрабатываются вручную** (`Policy::none()`): только `https`, хост из белого списка
    `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`.
  - Следующий запрос идёт **без** `Authorization`.
- **Кэш:** паки — `<стенд>\.quarknet\packs\<sha256>.zip`. Пак с совпадающим sha уже лежит → не качается.
- **Докачка:** `.part` + `Range: bytes=<n>-`.
  - Сервер ответил `200` вместо `206` — качаем заново.
  - Подписанный URL протух (`403`) — берём новый через API.
  - Поддержку Range у CDN GitHub проверить на живом канале (T12). Без неё докачка вырождается в повторную загрузку
    пака — это несколько МБ, приемлемо.
- sha256 считается потоком при записи. Не совпал → `.part` удаляется, `HASH_MISMATCH`, одна автоматическая повторная
  попытка.
- Таймауты: соединение 10 с, чтение 30 с без байт. Повторы 5xx и таймаутов: 3 раза, 1/3/9 с.

### 3.7 Проверка и установка (транзакция)
Сборка ставится в стенд, где 62 тыс. записей. Сделать атомарной замену всех файлов нельзя. Поэтому атомарно
только **переключение «текущей сборки»**, а сам стенд — всегда детерминированная функция двух вещей: индекса GAMMA
и сборки N. Любую оборванную установку можно довести или откатить повтором.

1. **Качаю.** Недостающие паки → кэш (§3.6).
2. **Проверяю.**
   - Каждый пак распаковывается в `.quarknet\builds\<N>.tmp\layer\<слой>\<путь>` по правилам §8.4.
   - У каждого файла сверяются размер и sha256 с манифестом. Лишний файл в паке — `ARCHIVE_UNSAFE`.
   - Затем `rename(<N>.tmp → <N>)` — атомарно на одном томе — и маркер `.verified` с sha манифеста.
3. **Ставлю.**
   - Проверка «игра не запущена»: процессы с образом внутри `game\`, §5.5. Запущена → ждём (`waitingGame`).
   - План: `want(индекс GAMMA, сборка N)` против манифеста стенда — список операций «положить» и «убрать».
     Для обновления нашего слоя это сотни операций, сканирования GAMMA нет.
   - Журнал `.quarknet\txn.json` = `{id, from, to, gammaIndexSha, startedAt}` пишется (tmp + rename) **до** первой
     операции.
   - Операции идемпотентны: «убрать имя (без смены атрибутов) → положить ссылку/копию из проверенного источника».
   - Занятый файл (`ERROR_SHARING_VIOLATION`, антивирус) — 5 попыток: 0,2/0,5/1/2/4 с.
   - Затем контроль: sha нашего слоя, победившего в стенде, и exe в `bin` и `bin_b` (одинаковый хэш,
     `deploy.ps1` поймал старый exe в `bin_b` ночью 2026-10-23); файл пробы хоста (§5.6) пересоздаётся.
4. **Фиксация.** Манифест стенда и `stand.json {installedBuild: N, …}` пишутся (tmp + rename), затем `txn.json`
   удаляется. До этого «ИГРАТЬ» недоступна.
5. **Сбой на шаге 3** (ошибка, а не обрыв процесса) → тот же механизм ставит `from` (сборка `from` лежит в кэше);
   текст «вернула 10: <причина>».
6. **Старт с `txn.json`** → если `builds\<to>\.verified` на месте, план `to` выполняется заново полностью (это и есть
   «довести»), иначе — план `from`. Тост `TXN_RECOVERED`.

Почему не две копии стенда и переключение junction: 62 тыс. ссылок на каждое обновление (~30 с), сохранения и
`appdata` пришлось бы выносить, а junction в корне стенда противоречит правилу «через ссылки-папки не пишем» (§4.2).

### 3.8 Откат и хранение N сборок
- В кэше `.quarknet\builds\` лежат N последних проверенных сборок: по умолчанию 3, настройка 2–10. Всегда хранятся
  установленная, предыдущая и закреплённая.
  - Лишние удаляются после успешной установки. Паки без ссылок из оставшихся манифестов — тоже.
- «Откатить на 9» = установка 9 по §3.7.
  - Подтверждение: «Вернуть сборку 9? Сейчас 10. GAMMA не трогаем. Сохранения не трогаем; сохранение, сделанное в
    10, может не загрузиться в 9».
  - Протокол другой — красная строка «у 9 протокол 9: с напарниками на 10 не сыграть».
- После отката сборка **закреплена**. Лаунчер показывает «вышла 11», но сам не ставит до «Обновить» или «Снять
  закрепление». Иначе «ИГРАТЬ» сразу вернула бы 10.
- Сборки нет в кэше → `BUILD_NOT_CACHED`, лаунчер предлагает скачать её с GitHub, если релиз ещё там.

### 3.9 Протокол — когда предупреждать
- Новая сборка меняет протокол → в «Что нового» и «Обновлениях» метка «несовместима с 10: играть вместе можно,
  только когда обновятся все»; в доке подпись к кнопке обновления.
- Проверка хоста: другой протокол — красная строка, «ИГРАТЬ» неактивна (строка 9 §2.2).
- Откат на сборку с другим протоколом — §3.8.

Состояние лаунчера вне стенда:
- `%APPDATA%\QuarkNET Launcher\settings.json` — пути, ник, канал (без ключа), предпочтения;
- `%LOCALAPPDATA%\QuarkNET Launcher\logs\launcher.log` — ротация 5 × 2 МБ.

### 4.2 Правила сборки (перенос `mo2_stand.py`, 29 тестов — в Rust)
1. **Слои снизу вверх:** игра (без её `appdata\`) → engine → включённые моды → `overwrite` → core → gamma.
   - `modlist.txt`: первая строка — наивысший приоритет. Берутся строки `+`, имя через `trim` (хвостовой TAB у
     `425- Dynamic News…`). Строки `-`, `*` и `*_separator` пропускаются.
   - Включённый мод без папки — в отчёт, не ошибка (`+DarkasleQif's…`).
2. **Пути** сравниваются без учёта регистра, побеждает верхний слой. Пропускаются: `meta.ini` в корне мода,
   `*.mohidden`, папки `.git`.
3. **Пути MO2:** `[Settings] base_directory`, `mod_directory`, `overwrite_directory`, `profiles_directory` из
   `ModOrganizer.ini`, если заданы. Иначе `mods\`, `overwrite\`, `profiles\`. `mo2_stand.py` этого не читал.
4. **Ссылка или копия.**
   - Файлы игры и модов — жёсткие ссылки.
   - Копии: наши слои; места, куда пишет игра или скрипты GAMMA. Это корень стенда (MCM дописывает
     `fsgame.ltx`), `appdata\**`, корень `gamedata\`, корень `gamedata\configs\`, `bin\*.ini|*.log|*.txt` (ReShade).
   - Копия всегда записываемая.
5. **Файлы игрока** (новое): `gamedata\configs\axr_options.ltx` и всё в `appdata_a\`, `appdata_b\` (сохранения,
   `user.ltx`, `coop_player.key`, кеш шейдеров).
   - Если файл уже есть, пересборка и обновление его **не перезаписывают**. Сбросить — только кнопкой «Сбросить
     настройки игры».
6. **Никогда не писать в существующий файл:** сначала убрать имя, потом создать заново. Запись через ссылку меняет
   оригинал мода — vault «NTFS жёсткие ссылки».
7. **Ссылка на read-only файл** удаляется через `FileDispositionInfoEx` с `DELETE|POSIX_SEMANTICS|
   IGNORE_READONLY_ATTRIBUTE`. Атрибут общий с оригиналом и не меняется.
8. **Сначала все папки, потом удаления, потом раскладка.**
   - Junction/symlink где угодно в стенде останавливает работу до записи первого файла (`REPARSE_IN_STAND`).
   - Удаление — только если `realpath(родитель)` внутри стенда.
9. **Стенд не пишет:** в непустую папку без `.quarknet\stand.json` (`STAND_FOREIGN`); в папку, которая пересекается
   с Anomaly, MO2, модами или `overwrite` (`STAND_OVERLAP`); через границу тома (`CROSS_VOLUME`). Тихой копии
   70 ГБ нет; копия слоя игры с другого тома — только с явного согласия и расчётом места (§12).
10. **Метаданные источника** — только `fs::metadata(path)`: он открывает файл и читает MFT.
    `DirEntry::metadata()` из `read_dir` на Windows берёт данные записи каталога. Для жёстких ссылок она устаревает
    — та же грабля, что `os.scandir` в Python. Идентичность ссылки — `(VolumeSerialNumber, FileIndex)` из
    `GetFileInformationByHandle`.
11. **Манифест стенда** сохраняется и при ошибке — с фактическим состоянием, как `finally` в `mo2_stand.py`.
    Файлы, которых стенд не клал (`appdata_*`, `fsgame_*.ltx`), он не трогает.
12. **Удаление стенда** — только по манифесту и только созданное лаунчером. Без рекурсивного удаления через
    reparse points: junction снимается первым. Сохранения в `appdata_*` по умолчанию остаются, их удаление — отдельный
    флажок.

### 4.3 Первая сборка
Мастер вызывает `paths_validate`, затем `stand_setup`:
1. **Проверки:**
   - NTFS: `GetVolumeInformationW`;
   - стенд на одном томе с Anomaly и с папкой модов MO2 (серийный номер тома);
   - пробная ссылка: создать файл в `.quarknet\probe`, связать, сверить FileIndex, удалить;
   - свободно ≥ нужно: копии ~150 МБ + наш слой ~30 МБ + кэш сборок ~50 МБ + запас 2 ГБ под кеш шейдеров
     и сохранения;
   - процессор с AVX (`is_x86_feature_detected!("avx")`);
   - MO2 запущен → предупреждение.
2. **Канал:** скачать и проверить последнюю (или закреплённую) сборку — шаги «качаю · проверяю».
3. **Сканирую:** индекс источников (игра, моды профиля, `overwrite`) → `gamma-index.json`.
4. **Связываю и ставлю:**
   - раскладка по §4.2 в `game\`;
   - `bin_b\` — если включено второе окно;
   - `fsgame_a/_b.ltx` из `fsgame.ltx` стенда: cp1251; строка `$app_data_root$` переписывается на
     `appdata_a\`/`appdata_b\`; формат не узнан — ошибка, как в `deploy.ps1`;
   - `appdata_a\`/`_b\`: файлы `appdata\` модов (пресеты шейдеров) копируются, кроме `user.ltx`;
   - `user.ltx` при первом создании — копия `<Anomaly>\appdata\user.ltx` тестера (графика переезжает) плюс
     `coop_nick <ник>`. При двух окнах в обоих `g_always_active on`; у `b` ещё `rs_screenmode windowed`,
     `vid_mode 1280x720`. Поведение `deploy.ps1` — для второго окна.
5. Отчёт в `reports\`, `stand.json`, файл пробы хоста.

`deploy.ps1` кладёт exe ещё и в `<Anomaly>\bin` (S0, просьба владельца для своей машины). Лаунчер этого **не
делает**.

### 4.4 Второе окно на одном ПК
- По флажку: `bin_b\` — жёсткие ссылки на всё из `bin\`, плюс `appdata_b\`, `fsgame_b.ltx`. Движок не пускает
  второй процесс из той же папки exe: мьютекс по пути папки, `x_ray.cpp`.
- После каждой установки sha exe в `bin` и `bin_b` сверяются. Различие → копия exe поверх; снова различие →
  `FILE_LOCKED`.
- Запуск: §5.3. Предупреждение про память с GAMMA (≥ 32 ГБ).

### 4.5 Слой GAMMA: когда пересобирать
Три отпечатка — для разных вопросов:

| Отпечаток | Вопрос | Как считается | Цена |
|---|---|---|---|
| **Быстрый (QF)** | «GAMMA тестера изменилась?» — при старте и перед каждым «ИГРАТЬ» | sha256 по: нормализованный список включённых модов в порядке приоритета; для каждого мода `meta.ini` (размер, mtime) и наличие папки; `overwrite` целиком (rel, size, mtime); игра — `db\**` (size, mtime) и `gamedata\**`, `bin\**` (у GAMMA там 66 скриптов modded exes) | ≤ 200 мс |
| **Глубокий (DC)** | «Моды поменяли файлы на месте?» — `modpack_patches` GAMMA пишет поверх файлов модов, не трогая `meta.ini` | Полный обход источников (list + `fs::metadata`) против `gamma-index.json` | 2–15 с, фоном: при старте лаунчера (низкий приоритет), по «Проверить GAMMA» и не реже раза в сутки |
| **Переносимый (PF)** | «У хоста тот же набор модов?» — сравнивается между машинами, mtime не годится | Для каждого мода `h_mod` = sha256 по отсортированным `(rel_lower, size)` его файлов в `gamedata/`, `db/`, `bin/` без «пишущихся на ходу» по правилу движка (`axr_options.ltx`, `cache_dbg.ltx`, `localization.ltx(.bak)`, `*.log|*.txt|*.bak|*.tmp` — `is_runtime_written` в `coop_manager.cpp`). Так же — для псевдо-модов `<Anomaly>` и `<overwrite>`. `gammaFp` = sha256 по строкам `имя\th_mod` в порядке приоритета | Считается при сборке и пересборке слоя из индекса, бесплатно |

- QF или DC нашли изменение → `gamma.state = changed`, детали (добавлены/убраны/изменены моды, порядок), плашка над
  доком. «ИГРАТЬ» неактивна: хост всё равно отказал бы по `ContentMismatch`.
- «Пересобрать» — инкрементально: только изменившиеся записи. Ориентир — повторный прогон `mo2_stand.py` за 7,8–14 с.
- Обновление **нашего** слоя GAMMA не сканирует: план считается из кэшированного индекса (§3.7).
- Режим «чистая Anomaly» (без MO2): слоёв модов нет; QF и PF считаются по `<Anomaly>`; слой gamma не ставится.
  Вместо junction `db` из стокового `deploy.ps1` — тот же материализатор (ссылки на файлы игры). Это один путь кода
  вместо двух.

### 4.6 Решение: логика стенда в Rust, PowerShell-скрипты не вызываем
Факт, который решает дело: логика слоя GAMMA сейчас не в PowerShell, а в **Python** (`deploy.ps1 -Profile` вызывает
`python tools/mo2_stand.py`). У тестера Python нет. Значит, при любом выборе `mo2_stand.py` придётся переписать.

| | Вызов PowerShell 5.1 из пакета | **Перенос в Rust** |
|---|---|---|
| Объём | Переписать `mo2_stand.py` (372 строки) на PS + P/Invoke `FileDispositionInfoEx` через `Add-Type` (компилирует C# при каждом запуске); поправить `deploy.ps1`; парсить stdout для прогресса | ~900–1200 строк Rust + ~800 строк тестов (`qn-fs`, `qn-core::stand`, `gamma`) |
| Скорость (62 тыс. файлов) | `New-Item -ItemType HardLink` ≈ 2–5 мс на файл → 2–5 мин; через `Add-Type` быстрее, но +2–5 с на компиляцию | Нативно, ориентир ≤ 60 с первая сборка, ≤ 15 с повторная |
| Тестируемость | Pester 3.4 из коробки, без фейковой ФС; падение посреди работы не смоделировать | Трейт `Fs` + `MemFs`: тома, inode, junction, read-only, отказ после k-й операции; 29 тестов `mo2_stand` переносятся |
| Антивирусы | Неподписанный exe запускает `powershell -ExecutionPolicy Bypass` с `Add-Type` — классический признак дроппера (AMSI, эвристики) | Один процесс, без скриптов |
| Среда тестера | Constrained Language Mode/AppLocker на части ПК; кодировка консоли cp866/cp1251 и юникод в именах модов (`test_unicode_names`); политики выполнения | Нет зависимости |
| Ошибки и отмена | Убитый посреди записи процесс не выполнит `finally` манифеста; ошибки — локализованный текст | Типизированные ошибки, токен отмены, журнал |
| Подводные камни | `Copy-Item -Force` и robocopy пишут **сквозь** ссылку в оригинал; `Remove-Item -Force` снимает read-only у оригинала; `Remove-Item -Recurse` на junction в старых PS может удалить цель (vault) | Те же правила явно в коде и тестах |
| Риск | Два языка, прогресс и ошибки через текст | Расхождение с `mo2_stand.py` |

**Решение — Rust.** Риск расхождения закрывается так:
- все 29 тестов `tests/tools/test_mo2_stand.py` переносятся как Rust-тесты;
- дифференциальная проверка (T12): оба инструмента собирают стенд из `E:\GAMMA` в соседние папки, наборы
  `(rel, src, mode)` сравниваются. Ожидание — 0 отличий, кроме задокументированных: файлы игрока, `.quarknet`.

Из PowerShell-инструментов берём **логику, а не вызов**: аргументы `launch.ps1`, `fsgame_*`/`user.ltx` из
`deploy.ps1`, состав пакета из `package.ps1`. Публикация остаётся в PowerShell (§7): она работает на машине
владельца, где есть git, gh и движок.

Следующий шаг после v1 (предложение): `qn-stand.exe` из того же крейта как CLI для `deploy.ps1 -Profile`. Тогда
у разработки и тестеров одна реализация, а `mo2_stand.py` уходит на пенсию.

## 5. Игра

### 5.1 «Создать игру»
- Команда (cwd = `game\`):
  `bin\AnomalyCoopDX11AVX.exe -fsltx fsgame_a.ltx -smap<N> -coop_host <порт> -coop_nick <ник> -coop_autostatus <сек>`.
- Это аргументы `launch.ps1` без `-NewGame`/`-start`. Хост выбирает «Новая игра / Продолжить / Загрузить» в окне
  «Кооператив» внутри игры (сборка 9+). `-coop_host` открывает сессию, как только мир готов.
  - Автоматика `-NewGame` (запись `[character_creation]` в `axr_options.ltx`) остаётся инструментом разработки,
    лаунчер её не использует.
  - Миникарту в `axr_options.ltx` лаунчер не включает, в отличие от стокового `launch.ps1`: это настройки игрока.
- **«Твой адрес для друга»:** IPv4 адаптеров с пометкой VPN — Radmin `26.0.0.0/8`, Hamachi `25.0.0.0/8`,
  Tailscale `100.64.0.0/10`, ZeroTier по имени адаптера. Порт: «UDP 27960 должен быть открыт».
  - Внешний IP — только по кнопке «узнать внешний адрес» с пояснением, что запрос уйдёт на `api.ipify.org`.
  - Движок внешний IP не отдаёт: vault W4 menu.
- Порт хоста — настройка, по умолчанию 27960 (`kDefaultPort`).
- «Проверить себя» в режиме хоста — проба на `127.0.0.1:<порт>`: «Сессия открыта: 1 из 8, ждёт напарников».

### 5.2 «Подключиться»
- Команда: `bin\AnomalyCoopDX11AVX.exe -fsltx fsgame_a.ltx -smap<N> -coop_connect <ip:порт> -coop_nick <ник>
  -coop_autostatus <сек>`.
- Адрес — IPv4 или имя хоста, порт необязателен. ENet 1.3.18 — только IPv4.
- Разбор адреса — общий набор векторов `contracts/fixtures/addresses.json` для TS и Rust. Хранятся 8 недавних адресов.

### 5.3 Второе окно
- `bin_b\AnomalyCoopDX11AVX.exe -fsltx fsgame_b.ltx -smap<N> -coop_connect 127.0.0.1:<порт> -coop_nick <ник>_2
  -coop_autostatus <сек>`.
- Кнопка «Запустить второе окно» появляется в доке, когда запущено окно `a` в режиме хоста и в настройках включено
  второе окно.

### 5.4 Ник
- `[A-Za-z0-9_.-]`, 2–24 символа. Движок читает `-coop_nick` как ANSI-токен без пробелов в `string64`
  (`coop_manager.cpp`).
- Пишется и в аргумент, и в `user.ltx` (`coop_nick`).

### 5.5 Процесс игры
- Запуск — `std::process::Command` с вектором аргументов, без оболочки. Аргументы строит чистая функция
  `launch::args()`. Тест сверяет её с выводом `launch.ps1 -NoStart` на тех же входах.
- **Слежение:** pid → события `starting/running/exited`, код выхода. Краш — код ≠ 0 и свежий `*.mdmp` в
  `appdata_X\logs\` → «Игра упала — отправь логи».
- **«Игра запущена»** определяется по процессам, у которых путь образа внутри `game\` (`QueryFullProcessImageNameW`).
  Так видны и окна, запущенные не лаунчером.
- **«Показать окно»:** `EnumWindows` по pid → `SetForegroundWindow`.
- **«Закрыть игру»:** `WM_CLOSE`. Через 10 с — «Завершить принудительно?» (`TerminateProcess`) с предупреждением о
  несохранённом.

### 5.6 «Проверить» — контракт запроса к движку (QNP v1)
Реализацию в движке делает отдельная задача E1 (PLAN §5). Здесь — контракт.

**Варианты:**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Вход ENet + сообщение `Probe` без `Hello` | Свой протокол | В лаунчере нужен ENet (`rusty_enet`); занимает слот пира — при «сервер полон» ответа нет; рукопожатие ENet ~3 RTT |
| B. Свой порт (27961) | Изоляция | Второй порт пробрасывать в роутере и разрешать в брандмауэре |
| **C. Сырой UDP-пакет на порт сессии, перехват `ENetHost::intercept`** | Тот же порт и правило брандмауэра; в сессию не входит; в лаунчере обычный `UdpSocket`; ответ за 1 RTT | Свой формат и защита от отражения |

**Выбор — C.**
- В ENet 1.3.18 есть `ENetInterceptCallback intercept` (`enet.h:346,397`): «1 — перехвачено, 0 — дальше в ENet».
- Пакет с нашей сигнатурой не похож на пакет ENet. Первые байты `QN` дают peerID 0x14E с флагом сжатия, такого пира
  нет, ENet его и так отбросит. Вероятность спутать с настоящим трафиком нулевая.

**Транспорт.** UDP, IPv4, на порт сессии хоста. Отвечает только машина в роли хоста, у которой открыт ENet-хост:
`Hosting` — мир грузится, `Live` — в игре. В главном меню порта нет → таймаут → «хост не отвечает — игра у него
запущена и мир загружен?».

**Запрос** (лаунчер → хост), всегда ровно **1200 байт**. Целые — little-endian.
```
off size поле
0   8    magic   "QNPROBE" + 0x01              51 4E 50 52 4F 42 45 01
8   1    kind    1 = INFO, 2 = DETAIL
9   1    page    номер страницы для DETAIL, 0 для INFO
10  2    reserved = 0
12  4    nonce   u32, случайный
16  1184 нули (выравнивание: ответ никогда не больше запроса)
```
**Ответ** (хост → лаунчер), ≤ 1200 байт.
```
0   8    magic   "QNREPLY" + 0x01              51 4E 52 45 50 4C 59 01
8   1    kind    эхо
9   1    status  0 ok, 2 detail отсутствует, 3 страница вне диапазона
10  2    reserved = 0
12  4    nonce   эхо
--- INFO (kind 1, status 0) ---
16  4    protocol        kProtocolVersion
20  1    phase           1 = мир грузится (Hosting), 2 = Live
21  1    players         включая хоста
22  1    max_players     kMaxPlayers
23  1    reserved
24  8    content_fp      u64, manifest_fingerprint(Manager::manifest())
32  4    content_entries u32
36  …    str build_id    (u8 len + UTF-8, ≤ 63; "anomaly-coop p10 Oct 23 2026 21:41:07")
         str host_nick   (u8 len + UTF-8, ≤ 63)
         u16 summary_len + summary bytes (≤ 512, непрозрачно — из файла пробы)
         u32 detail_len  (0 = нет)
         u8  detail_pages
--- DETAIL (kind 2, status 0) ---
16  1    page
17  1    pages
18  2    len (≤ 1100)
20  len  байты detail[page*1100 .. page*1100+len]
```
Невалидный запрос — длина ≠ 1200, чужая сигнатура или версия — `intercept` возвращает 0 (дальше в ENet) и не
отвечает.

**Файл пробы.** Движок читает `$fs_root$\quarknet_probe.bin`; его пишет лаунчер при каждой установке и пересборке.
- Формат: `"QNPF"`, `u8 version = 1`, `u16 summary_len`, summary, остаток = detail. Всего ≤ 64 КиБ, больше — файл
  игнорируется с одной строкой в логе.
- Движок содержимое **не разбирает**.
- Перечитывает при начале хостинга и не чаще раза в 5 с при смене mtime.
- Файла нет — `summary_len = 0`, `detail_len = 0`. Это «хост без лаунчера», например стенды владельца через
  `deploy.ps1`.
- Формат summary и detail — забота лаунчера:
  - summary (JSON ≤ 512 Б): `{"v":1,"b":11,"p":10,"l":"<layerSha12>","m":"gamma","g":"<gammaFp16>","n":578}`;
  - detail (JSON): `{"v":1,"mods":[["<имя мода>","<h_mod12>"],…]}`, вместе с псевдо-модами `<Anomaly>` и
    `<overwrite>`. Для GAMMA ≈ 35 КБ ≈ 32 страницы; запрашивается, только если `gammaFp` разный.

**Защита (движок):**
- ответ ≤ запроса — коэффициент отражения ≤ 1;
- лимиты: на IP 10 запросов/с с запасом 40 (листание detail), всего 200/с; сверх лимита — молча без ответа;
- состояния на запрос не создаётся;
- `intercept` вызывается внутри `enet_host_service` — в том числе из потока keep-alive (`event == NULL`, W9). Он
  читает только снимок `{protocol, phase, players, max, content_fp, entries, build_id, nick, файл}`. Главный поток
  обновляет снимок под своим мьютексом; `intercept` берёт его через `try_lock`, при неудаче — последняя копия.
- `kProtocolVersion` не меняется: проба вне протокола сессии, у неё своя версия в сигнатуре.

**Лаунчер:**
- 3 попытки: 0 / 400 / 1000 мс, общий таймаут 2,5 с. DNS — с таймаутом 2 с. Ответ принимается только с адреса
  запроса и с тем же nonce.
- RTT показывается как «отклик 42 мс».
- **Вердикт** (`qn-core::probe::verdict`):

| Сравнение | Источник у нас | Источник у хоста | Итог |
|---|---|---|---|
| протокол | `installed.protocol` | INFO `protocol` | разный → нельзя |
| сборка | `installed.build` | summary `b` | старше/новее → нельзя (§2.2 строки 10–11); summary нет → «неизвестно» |
| режим | `gamma` / `stock` | summary `m` | разный → «у хоста GAMMA, у тебя чистая Anomaly» |
| моды | свой `gammaFp` | summary `g` | разный → листаем detail → список «только у тебя / только у хоста / разные версии» |
| `build_id`, `content_fp` | — | INFO | в окне «подробно», для диагностики; при входе их всё равно проверяет движок |

Векторы байтов `contracts/probe/vectors.json` общие для тестов Rust (T9) и C++ (E1).

### 5.7 Протокол — сводно
Сравниваются три места: проверка хоста (§5.6), новая сборка (§3.9), откат (§3.8). Тексты — DESIGN §11:
«хост на сборке 9 — попроси обновиться», «у хоста сборка 11 — обнови», «у 9 протокол 9: с напарниками на 10
не сыграть».

## 7. Публикация с моей стороны — `tools\publish.ps1` в `anomaly-coop`

Одна команда. Работает на машине владельца: PowerShell 5.1, git, gh 2.101, движок в `engine-ci`.

```
powershell -ExecutionPolicy Bypass -File tools\publish.ps1 -Build 11
    [-Notes notes.txt | -Note "+ Группа ждёт всех у перехода — держи F" -Note "! Хост не вылетает …"]
    [-Prerelease] [-Repo owner/quarknet-builds] [-OutDir temp\publish]
    [-Upload [-Yes]] [-Promote 11] [-GhPath gh] [-QnTool <путь к qn-tool.exe>]
```

1. **Номер.** `-Build N` обязателен и больше последнего опубликованного: локальная запись
   `releases\quarknet\build-*\manifest.json`, а при `-Upload` — ещё и `gh release list`. Номер не переиспользуется.
2. **Только закоммиченное.**
   - Проект: `git archive --format=zip HEAD gamedata` (+ `gamedata_gamma`, если есть в HEAD).
   - Движок: `git -C engine archive --format=zip HEAD gamedata`.
   - Распаковка `System.IO.Compression` — без `tar`.
   - Незакоммиченные правки в этих путях: предупреждение со списком «в сборку не попадут». Публикация не
     прерывается — берётся HEAD.
3. **exe.**
   - Берётся `engine-ci\_build\_game\bin_dbg\AnomalyDX11AVX.exe` → `bin/AnomalyCoopDX11AVX.exe`.
   - Новое (задача P1): сборочный скрипт переезжает в `tools\build_ci.sh` (сейчас `temp\build_ci.sh`) и после
     успешной сборки пишет `engine-ci\_build\_game\bin_dbg\quarknet_build.json`:
     `{engineCommit, builtAt, exeSha256, configuration: "DX11-AVX"}`.
   - `publish.ps1` отказывается, если `engineCommit ≠ git -C engine rev-parse HEAD` или sha exe не совпал:
     «exe собран не из HEAD движка — запусти tools\build_ci.sh».
   - Проверки из `package.ps1`: заголовок MZ, ≥ 8 МБ, старше 60 с.
4. **Исключения** — как `package.ps1`: `axr_options.ltx`, `cache_dbg.ltx`, `*.bak|*.tmp|*.log|*.orig|…`,
   `temp\`, `.git`. Тест проверяет, что runtime-файлы не попадают в пак.
5. **Факты.** `protocol` и `maxPlayers` — из `git -C engine show HEAD:src/xrCoop/coop_protocol.h`
   (`kProtocolVersion`, `kMaxPlayers`); коммиты — полные sha HEAD проекта и движка.
6. **Паки и манифест.**
   - 4 детерминированных zip (§3.2), `manifest.json` по §3.3.
   - Проверка — `qn-tool manifest check manifest.json --packs <dir>`, тот же валидатор, что в лаунчере. Нет
     `qn-tool` — базовые проверки на PS и предупреждение.
   - Подпись (P1, когда появится ключ) — `qn-tool sign`. Ключ — по пути из `QUARKNET_SIGN_KEY`, пароль — из
     `QUARKNET_SIGN_PASSWORD`. Значения нигде не печатаются.
7. **Changelog.**
   - `-Notes`/`-Note`: строки `+ ` новое, `! ` исправлено, `~ ` изменено, `? ` известная проблема; ` — ` отделяет
     подсказку.
   - Без них — темы коммитов с прошлой опубликованной сборки (`prev.project.commit..HEAD`, то же для движка) без
     префиксов `docs|tests|chore`, всё как `change`. Скрипт предупреждает: «описание из коммитов — для игрока лучше
     -Notes».
   - `commits` в манифест идут всегда.
8. **По умолчанию — проба без загрузки.**
   - Печатается таблица ассетов (имя, размер, sha12), changelog, протокол против прошлой сборки («протокол
     меняется 10 → 11 — все должны обновиться»).
   - Финальная строка: «Ничего не загружено. Загрузка: -Upload».
9. **`-Upload` — только по слову владельца.** Агент не передаёт `-Upload` без явного «выкладывай» в чате.
   - `gh auth status`; тег `build-N` не существует.
   - Подтверждение «Загрузить сборку 11 в owner/quarknet-builds (свежие)? [y/N]» — пропускается только с `-Yes`.
   - `gh release create build-N <assets> --repo <repo> --title "Сборка N" --notes-file <changelog.md>
     [--prerelease]`.
   - Сверка: `gh release view build-N --json assets` (имена, размеры); `gh release download build-N -p
     manifest.json` и сравнение sha.
   - Запись `releases\quarknet\build-N\manifest.json`.
10. **`-Promote N`** — `gh release edit build-N --prerelease=false --latest`, с подтверждением.
11. **Тесты** (pytest, как `tests/tools/test_packaging.py`): пробный прогон в `-OutDir` на текущем репозитории
    (пропуск, если нет exe):
    - структура манифеста;
    - детерминизм — два прогона дают одинаковые sha паков;
    - исключения;
    - отказ на устаревшем `quarknet_build.json` и на занятом номере;
    - разбор `-Note`;
    - `-Upload` с подставным `-GhPath` (`.cmd`, пишет аргументы в файл) — команда собрана верно, сети нет.

## 8. Безопасность

### 8.1 Ключ доступа
- Только Credential Manager (§3.5). В процессе — `SecretString`; заголовок — `set_sensitive`.
- Фильтр `tracing` вырезает `gh[pousr]_[A-Za-z0-9]{20,}`, `github_pat_[A-Za-z0-9_]{20,}`, `Bearer\s+\S+`.
  Тест прогоняет через логгер строки с ключом.
- В URL ключа нет никогда. В WebView он попадает только при вводе и обратно не возвращается. Аргументы команды
  `channel_set_token` не логируются.
- Удалить ключ — «Удалить» в настройках; при удалении лаунчера ключ остаётся в Credential Manager, об этом
  сказано в «Помощи».

### 8.2 Сеть
- TLS — rustls, системные корни через `rustls-native-certs`. Только `https`.
- Хосты — белый список §3.6. Редиректы вручную, без ключа на чужой хост.
- Из WebView запросов нет (CSP).
- Внешний IP — только по кнопке (§5.1).

### 8.3 Целостность
- sha256 каждого пака (при скачивании) и каждого файла (при распаковке и после установки).
- Манифест приходит по TLS с GitHub; подлинность обеспечивает аккаунт владельца.
- **Подпись манифеста (P1):** ed25519 в формате minisign, открытый ключ зашит в лаунчер.
  - С версии, где ключ появился, неподписанный манифест отвергается (`MANIFEST_SIGNATURE`).
  - Подписан манифест — подписаны и все паки через их sha.
  - Ключ один на сборки и updater лаунчера (§9). Хранится вне репозиториев (KeePass / Secret Location Registry),
    в vault — только «где лежит».

### 8.4 Архивы (zip slip)
Путь записи в zip и `files[].path` манифеста проверяет `qn-core::relpath` — тип `SafeRel`, создаётся только
проверкой. Отвергается:
- разделитель `\`; пустые сегменты; `.` и `..`; ведущий `/`; буква диска (`C:`); `:` где угодно (ADS);
- управляющие символы; точка или пробел в конце сегмента;
- зарезервированные имена `CON PRN AUX NUL COM1–9 LPT1–9`, в том числе с расширением;
- длина > 240 символов;
- не NFC — нормализуем и сравниваем, расхождение — отказ.

Кроме того:
- запись должна быть в `files` манифеста с тем же паком, размером и sha. Лишние, недостающие и повторные без учёта
  регистра — отказ всего пака;
- записи-ссылки (unix-режим `S_IFLNK` во внешних атрибутах) — отказ;
- распакованный размер — не больше заявленного в манифесте; поток режется на заявленном размере (zip-бомба);
- путь назначения собирается покомпонентно от `builds\<N>.tmp\layer\<слой>` и проверяется, что остаётся внутри.
  Файлы создаются с `CREATE_NEW`;
- в стенд путь попадает только с разрешённым для слоя префиксом (§3.3). Подменённый манифест не положит
  `bin\dxgi.dll` и не тронет `appdata_*`.

Тесты — набор вредных архивов, собранных в коде теста, и `proptest` по `SafeRel`.

### 8.5 Файловая система
- Все записи — через `StandRoot`: канонический путь стенда. Перед работой проверяется, что в цепочке нет reparse
  points (§4.2.8). `Fs`-операции принимают только `SafeRel` относительно него.
- Источники (Anomaly, MO2, моды) открываются **только на чтение**. Тест на `MemFs` проверяет, что после первой
  сборки, обновления, отката и восстановления в томах-источниках не изменилось ни одного байта и атрибута.
- Пути из WebView (выбор папок) проверяет Rust (`paths_validate`). Команды записи принимают только сохранённые
  настройки.

### 8.6 Процессы
- Запускаются только `game\bin\AnomalyCoopDX11AVX.exe` и `game\bin_b\…`. Аргументы — вектор: ник и адрес
  проверены, без кавычек и пробелов. Оболочек нет; PowerShell лаунчер не вызывает вовсе.

### 8.7 WebView
- Capabilities минимальные (§1.6). Нет `shell`, `fs`, `http`, `opener` с произвольными URL.
- «Открыть папку» — команда `open_folder(kind)` с перечислением, не с путём.
- CSP без `unsafe-inline` и `unsafe-eval`. Внешних шрифтов и скриптов нет.

### 8.8 Проба хоста (лаунчер)
- Разбор ответа ограничен длиной и полями. Строки ≤ 63 байт, summary ≤ 512, detail ≤ 64 КиБ, страниц ≤ 64.
- JSON summary/detail разбирается `serde` в строгие типы. Ник хоста показывается как текст, не HTML.

### 8.9 Подпись exe — позже
- Лаунчер и exe движка пока без подписи Authenticode.
- План: Azure Trusted Signing (~$10/мес) или OV-сертификат — решение владельца после первых тестов (§11).
- До подписи — SmartScreen на установщике: «Подробнее → Выполнить в любом случае». Инструкция в README релиза
  и в «Помощи».

### 8.10 Антивирусы
- Чем меньше подозрительного, тем меньше ложных срабатываний:
  - один процесс без скриптов и `-ExecutionPolicy Bypass`;
  - нет упаковщиков (UPX);
  - есть метаданные версии и издателя;
  - скачанные файлы без Mark-of-the-Web: качает Rust, а не браузер.
- exe движка неподписан и редок → Defender может удалить его или заблокировать запуск. Признаки: после установки
  exe нет (`EXE_MISSING`), или `CreateProcess` вернул `ERROR_VIRUS_INFECTED (225)` / `ERROR_ACCESS_DENIED`. Тогда
  «Помощь → Антивирус»:
  - как вернуть файл из карантина;
  - как **самому** добавить папку стенда в исключения.
- Лаунчер исключения не добавляет и настройки защиты не меняет.
- Владельцу: при ложном срабатывании — отправить файл в Microsoft (форма submission).
- Временная блокировка файла при сканировании — повторы (§3.7). Жёсткие ссылки содержимое не пишут и сканирование
  не вызывают.

### 8.11 Логи и приватность
- `launcher.log` пишет действия, коды ошибок, длительности и пути, где `C:\Users\<имя>` заменено.
- Не пишет ключ, заголовки и тела ответов GitHub.
